# 角色生日推送 · v2.0.0

从萌娘百科获取角色生日及出处，按 **Galgame / 二次元游戏 / 番剧 / 全部** 订阅，每天按北京时间推送。保留原有指令，重写了抓取、缓存和调度逻辑。

## 安装与升级

1. 在 AstrBot WebUI 停用旧插件，使用新版安装包替换插件目录，或将源码文件夹放入 `data/plugins/astrbot_plugin_anime_birthday/`。
2. 保留 `data/plugin_data/astrbot_plugin_anime_birthday/` 中的原有数据，然后启用或重载插件。
3. 在会话发送 `/生日订阅 游戏`，也可选择 `gal`、`番剧`、`全部`。
4. 默认每天 **08:00（北京时间）** 推送；修改配置后重载插件使全部设置生效。

依赖 Python 3.10+、AstrBot 的 `initialize/terminate` 生命周期与 `StarTools.get_data_dir` 接口；唯一第三方依赖是 `aiohttp`。SQLite 使用 Python 标准库，不需要安装数据库服务。

## 本地缓存

数据存放在 AstrBot 数据目录下：

```text
data/plugin_data/astrbot_plugin_anime_birthday/
├── birthdays.sqlite3   # 生日、作品分类、订阅与各会话最后发送日期
└── state.json          # 如存在旧数据，迁移后保留原文件
```

- **按需积累**：第一次查询或推送某个日期时抓取并存盘。没有预装全年生日数据，也不会在启动时集中抓取全年页面。
- **跨重启复用**：按 `月-日` 保存，最多 366 个日期；不再因为超过 40 个日期而删除生日缓存。
- **有效期**：生日默认 30 天、作品类型默认 180 天。过期仅在使用时更新，旧数据不会因过期被删除。
- **断网后备**：更新失败时保留并使用已有数据，消息会注明使用本地后备。没有缓存时报告失败，不将错误保存成“无人生日”。
- **短期结果**：真正的空分类缓存 6 小时；首次抓取不完整时缓存 10 分钟并提示。已有旧数据时，不用不完整的新结果覆盖它。
- **过滤不影响缓存**：保存未经订阅类型或出处开关过滤的结果，发送时再筛选，切换偏好无需重新抓取。
- **手动更新**：`/生日刷新 3月8日` 跳过生日缓存有效期，但仍复用有效的作品分类缓存，并遵守并发合并、限速与失败冷却。

旧版 `state.json` 自动迁移一次：支持列表形式的订阅和带类型的订阅。`v3-M-D` 生日缓存及可识别作品分类作为后备导入；旧缓存没有可靠的更新时间，首次使用会尝试更新。无法判断含义的旧 `both` 分类、早期歧义 `gal` 分类重新判定。旧文件不被修改；如果 JSON 损坏，修复后重载插件会再次尝试迁移。

## 性能优化

| 场景 | 新行为 |
| --- | --- |
| 同一天多人同时查询 | 共用一次抓取任务，单个查询取消不影响其他等待者 |
| 已缓存的近期日期 | 从最多 8 个日期的内存缓存直接读取，无网络请求或数据库读取 |
| 其他已缓存日期 | 仅从数据库读取对应日期，不把全年角色载入内存 |
| 标题带作品前缀 | 如 `碧蓝航线:角色`，直接取得出处，省去角色页请求 |
| 同一作品多个角色 | 复用作品分类，内存最多保留 256 部作品，其余按需读盘 |
| 多个订阅会话推送 | 一批只取一次数据，同类型文本只渲染一次 |
| 无订阅 | 定时任务等待订阅变化，不轮询、不抓取 |
| 日常定时 | 直接等待下次推送或重试时间，订阅变化时唤醒 |
| 网络请求 | 复用一个 HTTP 会话，最多一个连接，请求间隔至少 500 毫秒 |
| 文件与页面解析 | 数据库操作和 HTML 解析在线程中执行，减少阻塞机器人事件循环 |

最多允许 8 个不同日期的查询任务排队，所有日期共用一个抓取队列。响应正文限制为 4 MiB；合并转发默认最多显示 100 个角色，避免异常数据或大量节点占用过多内存。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/今日生日` | 查询今天，按类型分组 |
| `/今日生日 番剧` | 查询今天的番剧角色 |
| `/生日查询 3月8日 游戏` | 指定日期、可选类型，优先读缓存 |
| `/生日查询 3-8` | 也支持 `3/8`，支持 `2月29日` |
| `/生日订阅 gal` | 订阅 Galgame 角色 |
| `/生日订阅 游戏` | 订阅其他二次元游戏角色 |
| `/生日订阅 番剧` | 订阅动画角色 |
| `/生日订阅 全部` | 订阅全部类型 |
| `/生日退订` | 取消当前会话的订阅 |
| `/生日订阅列表` | 查看会话及偏好 |
| `/生日测试` | 立即向全部订阅会话推送，不改变当天自动推送记录 |
| `/生日缓存` | 查看缓存日期、角色条数、作品数及文件大小 |
| `/生日刷新` | 尝试更新今天的生日数据并显示结果 |
| `/生日刷新 3月8日` | 尝试更新指定日期 |

默认只有管理员可执行订阅、退订、列表、测试、缓存状态和刷新操作。查询指令无需管理员权限。

## 推送与故障处理

- 使用北京时间，与服务器时区无关；正确支持 `00:00`。
- 启动时已过发送时间，会向当天尚未成功发送的订阅会话补发。
- 每次成功发送后，立即保存该会话的发送日期；其他会话失败不会影响已成功会话。
- 失败会话约 10 分钟后重试，当前运行期间每会话每天最多尝试 3 次。失败次数保存在内存，重启后重计；成功发送日期持久化。
- 已成功会话切换订阅类型仍保留当天发送记录；主动退订再订阅视为新订阅。
- HTTP 403/429 暂停请求 10 分钟；临时连接错误或服务器错误最多重试两次。分类分页失败、验证页面、循环分页均报错，不保存截断的生日列表。
- QQ `aiocqhttp` 平台可选合并转发，其他平台使用纯文本。主动消息能否发送仍取决于平台能力与会话有效性。
- 卸载时停止调度、取消共享抓取，并等待已有发送退出。

作品类型沿用基于正文与信息框的规则判定，可能存在误判；仅有成人分级文字不再直接判为 Galgame。有动画改编的游戏会同时出现在游戏与番剧推送中；无法判断的作品保守地进入各类订阅。

消息平台不提供统一的幂等发送接口。如果远端已收消息，但本地超时或在保存发送记录前进程退出，仍可能重复发送。发送记录的设计用于避免正常重试和重启造成的重复，不能保证平台级“恰好一次”。

## 配置

| 配置项 | 默认值 | 范围或说明 |
| --- | --- | --- |
| `send_hour` | 8 | 0–23，北京时间 |
| `send_minute` | 0 | 0–59 |
| `max_characters` | 30 | 1–200，每个文本分组显示上限 |
| `only_with_origin` | true | 隐藏无法识别出处的角色 |
| `use_forward` | false | QQ aiocqhttp 合并转发 |
| `admin_only` | true | 管理操作限管理员 |
| `birthday_cache_days` | 30 | 1–3650，生日缓存有效天数 |
| `work_cache_days` | 180 | 1–3650，作品分类有效天数 |
| `memory_cache_days` | 8 | 1–31，内存保留日期数 |
| `request_interval_ms` | 500 | 500–10000，请求最小间隔 |
| `request_timeout` | 20 | 5–120，单次请求超时秒数 |
| `max_forward_characters` | 100 | 1–200，转发角色数上限 |

## 开发与验证

模块分工：`main.py` 负责指令与调度，`birthday_service.py` 负责缓存与请求合并，`storage.py` 负责事务存储与迁移，`moegirl_api.py` 负责页面抓取和解析。

在插件目录运行：

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m pip install ruff
python -m ruff check .
python -m ruff format --check .
```

测试使用临时数据库、网页样例、HTTP 响应替身和 AstrBot 接口替身，覆盖并发缓存、重启复用、过期回退、旧数据迁移、分页、限速、日期校验、取消清理及逐会话补发。测试不会向真实群聊发送消息；仍需在自己的 AstrBot 部署中验证网页可用性和平台发送。

可选择手工验证抓取器（会访问萌娘百科；该命令只诊断抓取，不写入插件缓存）：

```bash
python moegirl_api.py 9 5 3
```

生命周期和主动消息调用按 [AstrBot 插件接口](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/star/base.py) 与 [主动消息文档](https://docs.astrbot.app/dev/star/guides/send-message.html) 接入；数据存储位置遵循 [AstrBot 插件存储规范](https://docs.astrbot.app/dev/star/guides/storage.html)。
